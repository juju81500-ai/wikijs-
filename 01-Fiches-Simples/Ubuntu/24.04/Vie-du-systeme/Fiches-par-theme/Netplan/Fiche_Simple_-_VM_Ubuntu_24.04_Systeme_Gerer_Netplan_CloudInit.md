# 📄 Fiche_Simple_-_VM_Ubuntu_24.04_Systeme_Gerer_Netplan_CloudInit.md

- **Environnement** : VM Ubuntu 24.04 provisionnée par cloud-init
- **OS / Version** : Ubuntu Server 24.04 LTS avec cloud-init et Netplan
- **Catégorie** : Système / Réseau / Provisionnement
- **Tags** : `[ubuntu24.04]`, `[ubuntu]`, `[cloud-init]`, `[netplan]`, `[reseau]`, `[systeme]`

## 🎯 Problème précis à résoudre
Identifier si cloud-init régénère la configuration réseau Netplan et transférer proprement cette responsabilité à une configuration locale persistante.

## 🧪 1. Hors-Production (Lab / Test / POC)
1. Examiner l'état et les fichiers de configuration :
   ```bash
   cloud-init status --long
   ls -l /etc/netplan/
   grep -R "generated by cloud-init" /etc/netplan /etc/cloud/cloud.cfg.d 2>/dev/null
   ```
2. Examiner les journaux sans désactiver cloud-init :
   ```bash
   sudo journalctl -u cloud-init-local -u cloud-init -u cloud-config -u cloud-final --no-pager
   ```
   👉 *Explication : les fichiers générés peuvent être réécrits lors d'un prochain démarrage ou reprovisionnement.*

## ⚡ 2. Production — Façon Simplifiée
1. Vérifier la source de vérité réseau dans l'hyperviseur ou la plateforme cloud. Préparer une configuration Netplan locale complète et conserver une copie des fichiers actuels.
2. Tester la configuration depuis la console avec :
   ```bash
   sudo netplan generate
   sudo netplan try
   ```
3. Seulement après validation de la configuration locale, désactiver la gestion réseau cloud-init avec `/etc/cloud/cloud.cfg.d/99-disable-network-config.cfg` :
   ```yaml
   network: {config: disabled}
   ```
   Puis redémarrer en fenêtre de maintenance et vérifier `cloud-init status --long`, `ip route` et `resolvectl status`.
   👉 *Explication : cette option désactive le rendu réseau cloud-init, pas cloud-init en entier. Ne pas supprimer l'ancien Netplan généré avant sauvegarde et validation de la configuration locale.*

## 🔒 3. Production — Façon Sécurisée
1. Ne pas désactiver cloud-init globalement si d'autres tâches de provisionnement en dépendent.
2. Ne pas basculer la propriété réseau sans console hors bande, copie de configuration et scénario de retour arrière.
3. Dans un cloud, respecter la méthode de provisionnement prise en charge par le fournisseur plutôt que de figer une configuration locale concurrente.

## ✅ Validation et retour arrière
- Après redémarrage, vérifier l'adresse, la route, le DNS, le statut cloud-init et l'accès distant depuis une seconde session.
- En cas d'échec, restaurer les fichiers Netplan et la configuration cloud-init sauvegardés depuis la console, puis réappliquer Netplan.
- Conserver le fonctionnement des autres modules cloud-init nécessaires à la machine.
